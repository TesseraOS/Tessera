## Lessons
- [a-decision-is-not-implemented-until-the-composition-root-implements-it](lessons/a-decision-is-not-implemented-until-the-composition-root-implements-it.md) — F-057 (metering): ADR-0056 §3 decided self-hosted is NOT capped and listed that as a delivered Positive; it was never true. `createRuntimeBilling` returns `createLocalBilling()` for `provider: 'none'`, that adapter reports every tenant free, and the clamp treated any present provider as metered — so from F-035 until F-057 **every** Local and self-hosted deployment was silently capped at the cloud free tier's 8000 tokens per compile, and enforcing the monthly cap under the same predicate would have hard-blocked them at 200 compiles/month. It survived a full review because the tests covered "no provider ⇒ no clamp" and "a provider ⇒ clamp" but never the shape the composition root actually produces (a provider IS wired and the deployment is NOT metered). An ADR states intent; the **composition root** decides whether it is true at runtime, and it is the only place that can silently disagree — especially when the consequence is a negative ("X is NOT capped"), because nothing fails when a negative stops holding. Detect capability **explicitly** (`metered = provider !== 'none'`), never structurally ("an object is present"), default to the safe answer, and test the default. Fix it in its own commit and re-run the gates that consume the changed value.
- [mutation-checks-audit-the-comment-not-only-the-code](lessons/mutation-checks-audit-the-comment-not-only-the-code.md) — F-057: every "mutation check: X turns this red" comment was actually RUN, and four of them were false — the bigint parse is load-bearing for 3 of 7 fields (float8 sums already arrive as numbers, so nothing can catch its removal there); REST failure isolation comes from Fastify's `onResponse` semantics, not from our `.catch`; nothing asserted the `metered` DEFAULT or `runtime.metered` at all; and deleting `pgSubscriptionMigrations` left all 129 tests passing. A mutation-check comment written from intuition is a hypothesis — running it audits the COMMENT as much as the code, and GREEN is a win too (missing assertion, or an over-claim to correct). Traps: `apps/*` consume workspace packages through their `dist`, so an unbuilt mutation presents as EVERY test timing out at 10s including `GET /health`, not as a focused failure; restore by writing back captured text, never `git checkout --` (it silently reverted an increment mid-session); and a malformed mutation reads exactly like a passing test, so prove the mutation did what you think before believing a GREEN.
- [a-protocol-client-disconnect-is-not-a-teardown-signal](lessons/a-protocol-client-disconnect-is-not-a-teardown-signal.md) — F-055 (remote MCP): the MCP SDK client's `close()` **sends nothing** — only `terminateSession()` issues the DELETE — so the ordinary case (an agent process exiting) strands a server forever. A session's lifetime belongs to whoever holds the memory, never to the peer: make the idle sweep the PRIMARY reaper (`unref` the interval), cap the map, and **assert the leak** (`sessionCount` still 1 after `client.close()`) — a happy-path-only test passes identically with no reaper at all. Reading the SDK source rather than its docs also produced the three other load-bearing facts: forward `parsedBody` or the request hangs on a stream the framework already drained; `Protocol.connect` throws on transport reuse, so "stateless" secretly means a new 20-tool server per request; and the SDK's bearer middleware rejects the non-expiring tokens this product issues. Mounting a raw protocol handler behind a web framework has a fixed shortlist: who parsed the body, whose headers survive a hijacked reply, what order shutdown runs in, and where an unexpected rejection goes. **Postscript (the evaluator pass):** all gates green and the feature still wasn't done — the ADR specified binding sessions on `(tenantId, principalId)` and the code bound `principalId` only, while the shipped test covered same-tenant/different-principal, which passes under BOTH implementations. Diff the implementation against the ADR clause by clause as its own step (the tests inherit whatever the spec's misreader believed), and when a control has two conditions, write the case that isolates each — then mutation-test both halves.
- [aria-idref-values-must-never-contain-free-text](lessons/aria-idref-values-must-never-contain-free-text.md) — F-053 (docs): fumadocs Tabs derives Radix ids from item text with `replace(/\s/, '-')` (FIRST space only), so a multi-word label leaks spaces into `aria-controls` — a space-separated IDREF list — and axe fails critical `aria-valid-attr-value` while `getElementById` says the target exists. When axe flags aria-valid-attr-value on generated ids, look for whitespace in the id first.
- [powershell-51-round-trips-mojibake-utf8-content](lessons/powershell-51-round-trips-mojibake-utf8-content.md) — F-053 (docs): PS 5.1 `Get-Content` without `-Encoding` reads BOM-less UTF-8 as ANSI; piping that through `-replace | Set-Content -Encoding utf8` mojibakes every non-ASCII char AND the replace silently misses (the pattern holds the real em-dash, the misread holds mojibake). - [booting-a-runtime-is-not-free-and-is-cwd-sensitive](lessons/booting-a-runtime-is-not-free-and-is-cwd-sensitive.md) — F-052 (`@tessera/cli`): `createServerRuntime`/`createLocalRuntime` is not cheap wiring — the `transformers` embeddings adapter loads its ~90MB model at CREATION (network on first run), so `init`'s smoke-boot is opt-in (`--verify`) and every runtime-booting test must default to `fake` embeddings. - [a-cursor-is-a-sort-order-not-just-a-page-boundary](lessons/a-cursor-is-a-sort-order-not-just-a-page-boundary.md) — F-063's acceptance asked for sortable columns AND cursor pagination; they are mutually exclusive, because `seq < cursor` is only a valid page boundary in `seq` order — a keyset cursor IS the ordering. The tempting fix (sort the loaded window) shows "sorted by actor" over page 1 of 40: the exact dishonesty the feature was deleting, shipped as a feature. - [move-facts-to-the-server-not-formatting](lessons/move-facts-to-the-server-not-formatting.md) — F-060 and F-061 both moved logic server-side so REST and MCP could not disagree, and both were right; F-062 nearly did it again for a Markdown export, which would have been wrong. The pattern is for **facts** the client could re-derive DIFFERENTLY (a count, a label, an entitlement) — two implementations can disagree about truth. A re-formatting of bytes the caller already holds has no truth to disagree about; an agent already has the whole package, for which Markdown is a lossier, fatter encoding. The test: "could client and server disagree about what is TRUE, or only about style?" A pattern that just paid off twice is the most dangerous kind — the *reason* transfers, not the shape. Corollary: read what a reuse candidate actually does — `buildExplanation` looked reusable and does the exact opposite (it strips the text an export exists to carry).

Fix: spawn the real binary directly (no shell/pnpm wrapper — Playwright’s `webServer` already does this everywhere else in the repo; web-perf was the one hand-rolled copy and the one that broke), kill the TREE (`detached` + `process.kill(-pid)` / `taskkill /T`), drain the pipes, preflight the port, and race the wait loop against child exit. Also: unfiltered `turbo run <task>` gives EVERY package a task node whose `^build` rebuilds the monorepo — `test:perf` built all 16 packages and neither app it measures. (CI repair, 2026-07-17.)
- [a-gate-that-errors-is-failing-open](lessons/a-gate-that-errors-is-failing-open.md) — `pnpm audit`’s 410 was not "npm broke our CI": an errored gate is neither pass nor fail, so nothing was being audited — it was hiding a live CRITICAL (vitest <3.2.6) and HIGH (vite <=6.4.2). Bumping `vitest ^2→^4` did NOT clear the high: `vite` was declared by nobody, existed only as an auto-installed peer, and pnpm reused the locked 5.4.21 — a required peer nobody declares is a dependency nobody owns or upgrades. Prove transitive fixes against the UPDATED lockfile; never infer them from version numbers. Repairing a gate must not change its policy (OSV-Scanner has no severity threshold, so it would have swapped "no high+" for "no vulns at any severity" by accident). And only `gates.json` gates get the ci-mirror guard — the `security` job was invisible to gate 0, which is how this rotted unseen. (ADR-0052.)
- [fullpage-screenshot-photographs-inview-reveals-blank](lessons/fullpage-screenshot-photographs-inview-reveals-blank.md) — the `/skills` capture came back blank below the hero while the e2e asserting those same headings passed, and BOTH were right: `Reveal` is `opacity:0` + `whileInView`, a `fullPage` screenshot never scrolls so nothing below the fold ever intersects, and Playwright `toBeVisible()` counts `opacity:0` as visible — so neither gate could see it. Walk the page before capturing, and capture an UNTOUCHED control page with the same script before blaming your change (the washed hero band reproduced identically on `/pricing`). Corollary that earned it: the same review caught Markdown backticks rendering literally in manifest prose — fields that render as plain text on ANY surface must be gated against Markdown syntax, because screenshot review is the only gate that reads the page as a reader does. (F-054.)
- [one-source-many-surfaces-split-the-entry-points](lessons/one-source-many-surfaces-split-the-entry-points.md) — feeding one source (a SKILL.md registry) to a marketing page, a CLI, and MCP tools: SPLIT THE PACKAGE ENTRY POINTS (`.` = manifests, `./content` = bodies) so a listing surface cannot ship a body through the module graph — a constraint expressible as a dependency edge beats one expressible as a convention (NFR-4 enforced structurally). Commit the derived artifact behind a regenerate-and-byte-compare gate, and PERTURB IT to prove it reddens before trusting it. Let derived data BE the schema (`z.enum(SKILL_NAMES)` makes `tools/list` publish the catalog). A cross-check spanning two packages that must not depend on each other lives in the CONSUMER. Verify vendor paths against primary docs — a wrong agent skills directory fails SILENTLY, and checking killed a fabricated per-skill compatibility list. Reuse the lowest existing permission for public content rather than rippling the RBAC catalog. (F-054.)
- [replay-the-original-miss-through-any-new-gate](lessons/replay-the-original-miss-through-any-new-gate.md) — a gate written AFTER a miss is authored while looking at the corrected text, which is by construction the one input guaranteed not to trigger it: the F-054 prose-count guard passed green and would still have shipped the exact bug, because replaying the five original sentences caught only four (a 24-char proximity window; the fifth put its noun ~43 chars away). Recover the pre-fix input with `git show <commit>:<path>` and run the rule against it, then PIN the regression set inside the test. Interrogate scope (line-scoped still lost to a line wrap — this prose wraps at ~85 and the offending line was 83; paragraph scope closed it at zero FPs). And a banned literal needs a sanctioned alternative or the rule is a trap. Effect-link half: E-026 inventoried everything that CONSUMES the generated data and missed the prose that QUOTES it — when a generated fact changes, grep content for the old VALUE, not just for importers. (F-054.)
- [unmetered-is-not-the-free-plan](lessons/unmetered-is-not-the-free-plan.md) — fixing F-077 meant copying REST's `services.billing ?? createLocalBilling()` into MCP, and copying it would have shipped a second bug: that fallback does not mean "no billing configured", it means "treat this deployment as a FREE-TIER CUSTOMER" (the local adapter reports a free subscription), so every self-hosted user was already capped at the cloud Free plan's 8000 tokens on REST and the fix would have extended it to agents overnight. A fallback that supplies a POLICY object rather than an empty value must NAME the policy — `??` reads as null-safety plumbing and hides the decision. Check what the requirement actually says (NFR-12 is cloud cost control, never "throttle someone running their own hardware"), and escalate product-shaped questions instead of inheriting them from a `??`. When a fix changes behaviour, REPLACE the pinning test with plural tests for the new behaviour so coverage rises. General rule: a defect fix is the moment you inherit every assumption in the code you are copying — read that line as a proposal, not a precedent. (F-077/ADR-0056.)
- [thread-scope-on-the-job-not-the-payload-or-a-closure](lessons/thread-scope-on-the-job-not-the-payload-or-a-closure.md) — carrying an isolation scope from a tenant-aware caller to a tenant-blind worker across a queue: put it on the JOB envelope as a REQUIRED field (optional + default fallback keeps the silent-default bug), give ports scoped forTenant/forProject VIEWS not a droppable (payload, scope) parameter, and NEVER on the content payload (it flows through plugin stages that return a new object = forgeable) nor resolved from a per-runtime map (dies when the worker becomes a separate process, falling back to default). The worker VALIDATES the boundary (missing scope throws, never defaults). Corollaries: a leak can hide one layer past the fix (audit every reader of an attribution you change — the SSE bridge); 'reported success' != 'did work' when the queue swallows failures (an honest `indexed` count, gated on being able to derive it); assert isolation on the keyword signal (fake embeddings have no relevance floor); rewriting a double for a widened port, assert on OUTCOMES not a spy of the base method (the worker calls the scoped view). (F-071/ADR-0057.)
- [loading-a-plugin-successfully-proves-nothing](lessons/loading-a-plugin-successfully-proves-nothing.md) — F-058 wrote a test named "the first-party connector actually asks before it walks a root" that asserted `status: loaded`; a mutation DELETING the `require(permission)` call left it green, because a plugin that never asks loads exactly as successfully as one that asks and is granted. A success assertion is satisfied by every path that reaches success, including the one where the guard is gone — so test a guard by constructing the variant where it SHOULD fire (strip the declaration, assert the same setup is refused), and run mutations on the production CALL SITE, not only the framework. Same shape found the same day in `settings.spec.ts`, whose axe assertion had been analysing the flags card ERROR branch because the route was never stubbed: an unstubbed dependency in a UI test does not fail, it silently renders a different branch. Also: report equivalent mutants as equivalent — claiming N/N red when one is unobservable is the same dishonesty. (F-058.)
- [workspace-star-hides-the-publish-set](lessons/workspace-star-hides-the-publish-set.md) — F-059 inherited a recorded publish set of 3 packages; @tessera/cli's real transitive closure is EIGHTEEN, so publishing 3 would have shipped a CLI failing on `npm install` with `404 @tessera/api@0.0.0 is not in this registry`. It was invisible because **`workspace:*` always resolves inside the workspace** — typecheck/lint/test/build/e2e are all green with a wrong publish set, and pnpm only rewrites `workspace:*` to a concrete version AT PACK TIME, so the hard requirement exists in no file you can read. A whole class: contracts that break INSTALLS rather than builds, which every build-shaped gate is structurally blind to (effect E-030). Compute the closure, never list it (derive the set from `private`, so it cannot drift from what `changeset publish` pushes); prove it by installing tarballs offline AND run the negative control, since a positive result alone does not show the old set was wrong; audit tarball contents (and beware a `secret` grep hitting `dist/secrets/*.js`, which is SecretsProvider CODE); use changesets `fixed` not `linked`, because a version skew between interdependent packages is an install failure. General rule: when the failure mode lives outside the repository, write the out-of-band proof and make it a REQUIRED checklist step, or it will never be run again. (F-059/ADR-0062.)
- [a-green-assertion-that-cannot-go-red](lessons/a-green-assertion-that-cannot-go-red.md) — F-064 produced FOUR tests whose result was not evidence of what their name claimed, each looking different: a wrong UNIT (reduced-motion "failed" against 724 durations of `1e-05s` — 0.01ms in scientific notation; the filter string-matched "0.01ms" and was one parseFloat from a test that could never go red), a wrong MOMENT (axe reported 727 contrast violations that vanished on retry — it was auditing during a dialog fade-in, sampling every element through a half-transparent overlay), a wrong DATE (`getByText('12')` without `exact` also matched the feed's "12d ago", so the test passed or failed depending on the day it ran — and went off the morning the fixture turned 12 days old), and a wrong CLAIM (a test named "the connector actually asks" asserted only that loading succeeded, which stays true with the permission call deleted). A passing test proves SOME path reached the assertion, not that the path you meant did. Make it fail on purpose once; parse rather than string-match anything a browser computes; await `document.getAnimations()` (with `.catch()` — cancelled animations reject) before any axe run on an animated surface; use `{ exact: true }`; and treat retry-green as a hypothesis, not a diagnosis — three of the four first presented as flakiness. (F-064/ADR-0063.)
